How the two implementations differ (short)
- Project A: single-threaded Flask dev server; the server writes the uploaded bytes and then calls a blocking `process_image` function whose simulated time scales linearly with size (0.15s/MB). This demonstrates a backend bottleneck under large files or concurrency.
- Project B: supports client-side chunked uploads (server assembles parts). Uses a ThreadPoolExecutor to simulate parallelized image processing and responds faster during chunk receipt; processing is done in background worker(s) which reduces per-request blocking time and improves throughput. Simulated processing cost is much lower (0.04s/MB) and split into chunks to model parallelization.
